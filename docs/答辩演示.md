# 答辩演示脚本

## 演示前 3 分钟

```bash
cd web
pnpm dev
```

1. Chrome 打开 `http://127.0.0.1:5178`，按 `F11` 全屏。
2. 右侧顶部「更多」菜单中的「全屏演示」也可以。
3. 确认右上角更新时间是当前时间；数据模式与口径可在右上角信息栏查看。
4. 关闭微信/QQ 弹窗，浏览器只留一个标签页。

## 5 分钟主线

### 0:00–0:40 总览：先给结论

> “这是电信流量运营平台的总览。数据是 2026 年 10 月 10 日到 11 月 8 日，31 个省、420 个重点小区，今天总流量 93.9 PB，晚高峰 20 点峰值 14.66 Tbps。”

指一下顶部 3 个核心 KPI、下方辅助指标，再指流量趋势和区域排名：

> “峰值出现在 20 点，峰均比 1.69；华东贡献 33.9% 的流量；44 个小区进入忙时高负载。”

### 0:40–1:20 联动：证明不是写死的

1. 点「近 7 天」→ KPI 与曲线变化。
2. 点「全国」→ 选「华东」→ KPI 变成华东口径。
3. 点「对比上期」→ 曲线多一条上期虚线。

> “所有图都是按当前时间和区域重新取数，不是静态图片。后端就绪后，这里只改一个环境变量就切到真实接口。”

### 1:20–2:00 时段分析：回答“高峰在哪”

1. 进「时段分析」。
2. 先看整周热力图，点击左侧「11-08」展开当天统计卡片和图表。
3. 指当天 24 小时分布，切「折线」或「柱状」，按需开启「日均线」和「对比前一天」。
4. 切换另一日期，展示当天总量、峰值、时段构成同步变化；24 小时明细可单独展开。

> “晚高峰贡献全天 25.2% 的流量，是扩容和保障的重点窗口。峰均比 1.69，说明网络还有弹性，但 20 点已经接近容量门限。”

### 2:00–2:40 区域分布：回答“流量在哪”

1. 进「区域分布」。
2. 地图上指广东、江苏、浙江。
3. 点「广东」→ 右侧出现省份详情、排名、同区域对比。
4. 切「增速」→ 地图换颜色，浙江 +4.9% 最快。
5. 表格点表头「同比」排序。

> “广东流量第一，浙江增长最快，贵州人均流量最高。这三个结论分别对应扩容优先级、营销投入和套餐设计。”

### 2:40–3:30 资源与扩容：回答“怎么优化”

1. 进「资源与扩容」。
2. 点「预警小区」卡片 → 表格只剩预警。
3. 点第一行 → 右侧抽屉：利用率、带宽、用户、近 7 天趋势。
4. 关抽屉，点「生成扩容建议」→ 弹窗列出 8 个小区和建议动作。
5. 点「下发工单」→ 成功提示。

> “这里把分析落到了动作：谁需要扩容、扩什么、预计缓解多少。答辩现场点‘下发工单’是模拟，真实环境接工单系统即可。”

### 3:30–4:20 实时监控：课程要求的流处理与负载均衡

1. 进「实时监控」，页面是深色大屏。
2. 指实时速率、消息流、3 个消费者、3 个分区。
3. 点「模拟缩容」→ worker-3 消失，分区 2 转给 worker-1，出现提示。
4. 点「恢复 3 消费者」→ 分区归还。
5. 点「暂停」再「继续」，点「2×」。

> “Kafka 主题 3 个分区，3 个消费者同组，一人一个分区；worker-3 退出后触发再均衡，分区 2 由 worker-1 接管，后续消息不丢。这就是课程里的分区级负载均衡。”

### 4:20–5:00 数据任务与收尾

1. 进「数据任务」。
2. 指链路：Kafka → HDFS → Spark/MapReduce → HBase → API → 可视化。
3. 指作业列表：Spark SQL、MapReduce、Flink。
4. 点失败的作业 → 「重新运行」→ 状态变化。
5. 展开底部「接口契约与指标说明」：查看只读接口与统计口径。

> “前端不是空中楼阁：数据链路、作业状态、接口契约都在这页。Quick BI 那边用同一份聚合结果做报表，我们自研前端负责交互下钻和实时演示。”

## 2 分钟压缩版

总览（30 秒）→ 时段热力图（20 秒）→ 区域地图点广东（25 秒）→ 资源页扩容建议（25 秒）→ 实时页模拟缩容（20 秒）。

## 可能被问的问题

**Q：数据真的经过分布式处理吗？**
A：是。采集进 Kafka，原始层落 HDFS，Spark/MapReduce 按小时、省、小区聚合，结果进 HBase，前端通过 API 读聚合结果。数据任务页能看到作业名、引擎、行数和输出路径。

**Q：怎么证明不是前端写死的？**
A：现场切时间范围和区域，KPI、曲线、地图、表格都会变；数据由固定种子的脚本生成，换种子或换后端数据，页面不用改。接口契约在 `docs/接口契约-v1.md`。

**Q：Quick BI 在哪里？**
A：组内用真实 Quick BI 出报表；这个前端是自研看板，负责交互下钻、实时演示和答辩效果。两边的指标口径一致，报告里有对照表。

**Q：实时页面是真的吗？**
A：Mock 模式下是前端模拟流；接后端时按契约里的 SSE 接口替换定时器即可，消费组分区和再均衡逻辑是真实课程实验里跑过的。

**Q：负载均衡怎么体现？**
A：看实时页右侧：3 个消费者各持 1 个分区；点「模拟缩容」后 worker-3 退出，分区 2 重新分配给 worker-1，消息继续消费。

**Q：为什么不用现成的后台模板？**
A：Quick BI 是浅色企业 BI 形态，实时监控需要深色大屏；现成模板的表格和图表风格不统一，这套设计系统和交互是围绕流量分析定制的。

## 翻车预案

| 情况 | 处理 |
| --- | --- |
| 后端没起来 | 保持 Mock 模式，右上角信息栏显示「本地模拟」，照常演示 |
| 端口被占 | `pnpm dev --port 5180` |
| 地图空白 | 刷新页面；GeoJSON 在 `public/geo/china.json`，不依赖外网 |
| 投影/分辨率不对 | 用 1920×1080，浏览器 100% 缩放；或点全屏按钮 |
| 数据被改乱 | 点右上角刷新；设置里“恢复默认” |
