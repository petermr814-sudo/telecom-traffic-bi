# 接口契约 v1

前端目前运行在 **Mock 演示模式**。后端就绪后只需实现本文件的 9 个只读接口，前端改两个环境变量即可切换，页面代码不用动。

## 1. 运行模式

```bash
# 演示模式（默认）
VITE_DATA_MODE=mock

# 真实接口模式
VITE_DATA_MODE=api
VITE_API_BASE=http://192.168.10.101:8080
```

- 开发环境：`vite.config.ts` 会把 `/api` 代理到 `VITE_API_BASE`，后端不需要配 CORS。
- 生产环境：推荐 Nginx 把 `/api` 与前端同域反代；若跨域直连，后端需允许 `GET`、`Content-Type`、`Authorization`。
- 鉴权：当前未启用。如需 Token，在前端 `src/api/client.ts` 的 `request()` 里统一加 `Authorization` 头即可，页面不用改。

## 2. 通用约定

| 项 | 约定 |
| --- | --- |
| 编码 | UTF-8，`application/json` |
| 字段命名 | 小驼峰 `camelCase` |
| 流量 | 整数，单位 **byte** |
| 速率 | 整数，单位 **bps** |
| 占比 / 利用率 | 0–100 的浮点数，不带 `%` |
| 时间 | `2026-11-08T21:00:00+08:00` 或 `2026-11-08 21:00:12` |
| 枚举-时间范围 | `today` / `7d` / `30d` |
| 枚举-区域 | `all` / `华北` / `东北` / `华东` / `华中` / `华南` / `西南` / `西北` |

统一响应信封（前端兼容裸 JSON）：

```json
{ "code": 0, "message": "ok", "data": {} }
```

`code = 0` 表示成功；非 0 时前端提示 `message`。HTTP 状态码仍需正确返回（400 / 401 / 500）。

## 3. 接口清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/meta` | 数据集元信息 |
| GET | `/api/v1/overview` | 总览 KPI + 24 小时序列 + 区域占比 |
| GET | `/api/v1/hourly` | 24 小时曲线与上期对比 |
| GET | `/api/v1/heatmap` | 7 天 × 24 小时热力图 |
| GET | `/api/v1/provinces` | 31 省明细 |
| GET | `/api/v1/cells` | 小区利用率与状态 |
| GET | `/api/v1/alerts` | 告警列表 |
| GET | `/api/v1/jobs` | 分布式作业列表 |
| GET | `/api/v1/pipeline` | 数据源与链路状态 |
| GET | `/api/v1/realtime/stream` | 实时流（SSE，预留，见第 5 节） |

### 3.1 `GET /api/v1/meta`

无参数。

```json
{
  "operator": "中国电信",
  "generatedAt": "2026-11-08T21:00:00+08:00",
  "dateStart": "2026-10-10",
  "dateEnd": "2026-11-08",
  "provinceCount": 31,
  "cellCount": 420,
  "records": 562400000,
  "mode": "mock",
  "contractVersion": "v1",
  "lastSync": "2026-11-08 21:00:12"
}
```

### 3.2 `GET /api/v1/overview`

查询参数：`range`、`region`、`warn`（预警阈值，默认 70）、`congest`（拥塞阈值，默认 85）。

```json
{
  "kpi": {
    "totalBytes": 93891671595479685,
    "activeUsers": 186400000,
    "peakBps": 14660000000000,
    "peakHour": 20,
    "busyCellRatio": 10.5,
    "fiveGShare": 68.1,
    "perUserBytes": 503700000,
    "delta": {
      "total": 0.2, "users": 0.9, "peak": 1.2,
      "busy": 0.8, "fiveG": 1.5, "perUser": 1.2
    }
  },
  "hourly": [1740000000000000, 1420000000000000, 1280000000000000],
  "compare": [1730000000000000, 1400000000000000, 1260000000000000],
  "peakIndex": 20,
  "regionShare": [
    { "region": "华东", "bytes": 31800000000000000, "share": 33.9 }
  ],
  "alerts": [],
  "topCells": []
}
```

说明：

- `hourly` / `compare` 固定 24 个元素，下标即小时（0–23）。
- `peakIndex` 是 `hourly` 最大值的下标，用于在图上标峰值。
- `regionShare` 固定 7 个大区，`share` 之和约 100。
- `alerts`、`topCells` 的结构分别同 3.7、3.6。

### 3.3 `GET /api/v1/hourly`

查询参数：`range`、`region`。

```json
{
  "current": [1740000000000000],
  "compare": [1730000000000000],
  "peakIndex": 20,
  "peakBytes": 6600000000000000,
  "avgBytes": 3900000000000000
}
```

- `current` / `compare` 固定 24 个元素。
- `peakBytes`、`avgBytes` 用于“峰均比”和日均线。

### 3.4 `GET /api/v1/heatmap`

查询参数：`region`。

```json
[[0, 0, 1726285988328512], [1, 0, 1388092373195604]]
```

- 每项 `[hour, dayIndex, bytes]`。
- `hour` 0–23；`dayIndex` 0–6，0 为最早一天，6 为今天。
- 固定返回 7 × 24 = 168 项。

### 3.5 `GET /api/v1/provinces`

查询参数：`range`。

```json
[
  {
    "province": "广东省",
    "region": "华南",
    "trafficBytes": 9000000000000000,
    "users": 19223000,
    "perUserBytes": 468000000,
    "share": 10.0,
    "growth": 1.6,
    "cells": 47
  }
]
```

- 31 条，`province` 必须与地图 GeoJSON 名称一致（如 `北京市`、`内蒙古自治区`、`广西壮族自治区`）。
- `growth` 为同比百分比。

### 3.6 `GET /api/v1/cells`

查询参数：`range`、`region`、`warn`、`congest`。

```json
{
  "rows": [
    {
      "id": "C0081",
      "name": "合肥住宅区4G宏站",
      "city": "合肥",
      "province": "安徽省",
      "region": "华东",
      "type": "4G宏站",
      "generation": "4G",
      "bandwidthMbps": 800,
      "users": 7664,
      "baseUtil": 88.2,
      "utilization": { "today": 99.5, "7d": 99.6, "30d": 99.7 },
      "trend": [86.1, 87.0, 88.2, 89.4, 90.1, 91.2, 99.5],
      "trafficBytes": 4000000000000,
      "busyMbps": 796.0,
      "util": 99.5,
      "traffic": 4000000000000,
      "status": "拥塞",
      "headroomMbps": 4
    }
  ],
  "total": 420,
  "summary": {
    "total": 420,
    "warning": 77,
    "congested": 24,
    "expandable": 101,
    "avgUtil": 54.9
  }
}
```

- `util` 是当前 `range` 下的利用率；`traffic` 是当前 `range` 的累计流量。
- `status` 由后端按 `warn`/`congest` 计算；前端也会用阈值展示，但以返回值为准。
- `trend` 固定 7 个点，用于详情抽屉。

### 3.7 `GET /api/v1/alerts`

无参数。

```json
[
  {
    "id": "AL0001",
    "time": "2026-11-08 20:58",
    "level": "严重",
    "region": "华东",
    "cellId": "C0081",
    "cellName": "合肥住宅区4G宏站",
    "metric": "忙时利用率",
    "value": "99.5%",
    "message": "忙时利用率超过 90%，出现排队",
    "status": "待处理"
  }
]
```

- `level`：`严重` / `警告` / `提示`。
- `status`：`待处理` / `已确认`。确认动作目前只在前端本地生效，若需持久化，请提供 `POST /api/v1/alerts/{id}/ack`。

## 4. 前端字段适配

页面只认 `src/api/types.ts` 里的模型。后端字段名不同时，改 `src/api/client.ts` 或加一层 `adapter` 即可，页面无需改动。日期、单位、区域枚举的转换都放在这一层。

## 5. 实时流（预留）

实时监控页当前用前端定时器模拟数据。接真实 Kafka 时按 SSE 实现：

```text
GET /api/v1/realtime/stream
Content-Type: text/event-stream
```

每 1–2 秒推送一条：

```json
{
  "rateBps": 12580000000,
  "msgPerSec": 128600,
  "consumers": [
    { "id": "worker-1", "host": "hadoop1001", "partitions": [0] }
  ],
  "partitions": [
    { "id": 0, "owner": "worker-1", "rateMbps": 42.8, "lag": 36 }
  ],
  "message": {
    "time": "22:46:35",
    "cell": "杭州西湖5G宏站",
    "action": "视频",
    "bytes": 71800000,
    "partition": 1
  }
}
```

前端接入点：`src/views/Realtime.vue` 的 `onMounted`，把定时器替换为 `EventSource` 即可；降级逻辑保留模拟流。

## 6. 验收方式

```bash
cd web
pnpm install
pnpm dev          # http://127.0.0.1:5178
pnpm build        # 产物在 web/dist
```

后端联调：

```bash
VITE_DATA_MODE=api VITE_API_BASE=http://192.168.10.101:8080 pnpm dev
```

浏览器打开后，右上角信息栏的「数据模式」应显示“真实接口”；若显示“本地模拟”，说明环境变量未生效。
